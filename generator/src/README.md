# Image Generator (Perchance) — project notes

Structure: `src/README.md` (this file) stays in root, docs live in `src/docs/`,
all JS lives in `src/lib/` grouped by feature (`core/`, `gallery/`, `modals/`,
`prompt/`, `ui/` — every group has 2+ files, so nothing sits loose in `lib/`).
`src/styles.css` + `src/defaults.json` stay in `src/` root.

All UI is generated by the
`t2i-framework-plugin-v2` import from the `settings` list in `main.pjs`; the
extra UI (per-image buttons, vary/style-compare modals, private gallery) lives in
the `<script>` blocks of `index.html`.

## Files

- `main.pjs`
  - `$meta` (title/description)
  - `settings.pageTitle`, `settings.numImages`
  - `settings.imageOptions` — what gets handed to `text-to-image-plugin`
    (`prompt`, `negativePrompt`, `resolution`, `guidanceScale`, `seed`,
    `forceColorScheme`). `prompt` is built from the selected art style's
    `prompt` template + the optional quality-boost `promptSuffix` + the
    optional `(steps:::N)` tag.
  - `settings.userInputs` — one entry per input in the UI. Names are how the
    code refers to them (`[input.description]`, `window.input.description`).
    `description` is the prompt textarea; its `modifiers` list renders the
    "add modifier…" dropdowns, which work by **appending text to the prompt**.
  - `settings.userInputs.steps` — Steps dropdown (see below).
  - `artStyle.options` — the art-style list; each style has `prompt`, `negative`,
    optionally `modifiers`, and `meta:tags` used for import-based ordering.
- `index.html`
  - `[generateHTML(settings)]` renders the whole generator UI.
  - Shell only (navbar, hero, footer, top button element). All CSS/JS
    lives in `src/lib/` and loads with `defer` in dependency order
    (observer → adapter → shared/modal → vary/style-compare → rest),
    so parsing never blocks on the scripts.
- `src/styles.css` — both former `<style>` blocks concatenated verbatim.
- `src/lib/core/observer.js` — single MutationObserver + rAF batching; features
  subscribe via `onProDomChange` / `offProDomChange`. Mutation batches
  accumulate (no dropped records). Replaces the per-feature observers
  and all polling timers.
- `src/lib/ui/scroll-fix.js` — overflow-unlock via the central dispatcher only
  (no own observer, no interval); skips while an overlay is open.
- `src/lib/core/framework-adapter.js` — single home for framework IDs/keys
  (`privateGalleryCtnId`, `generateButtonId`, `imageCtnSelector`,
  `settingsKey`) + getters (`getUserInputEl` is the one input-element
  lookup, with `#userInputsCtn`-scoped fallback). Update IDs here on plugin bump.
- `src/lib/core/shared.js` — image helpers + per-image buttons (`getImageData`,
  `dataKey`, `iframeSizeFor`, `makeSaveButton`, `saveImageToGallery`,
  `showToast`, `makeEmbed`, `copyTextToClipboard`, `fireInputEvents`
  (single copy; prompt-io/reset-defaults keep thin aliases),
  `makeImageActionButton`
  factory + `requireFinishedSeed`, regenerate/vary/copy-seed/style-compare
  buttons, `addButtonsToImages` via the central dispatcher (mutation
  batches scan added nodes only).
- `src/lib/gallery/fly-to-gallery.js` — ghost fly-to-gallery animation
  (`flyImageToGallery`, `saveToGalleryWithFly`). The framework animates
  saves toward `#privateGalleryCtn97364827 button`, but the dock moves that
  button — so this resolves the live target and overrides
  `window.t2i_privateGallerySave` (deferred install: the framework assigns
  its version after our scripts run) with identical save semantics.
- `src/lib/gallery/upscale-info-fix.js` — wraps `window.t2i_startUpscale` (snapshot
  prompt/seed/etc. into the pending entry while the live iframe still has
  it), `window.t2i_showUpscaleLightbox` (restore the snapshot when the
  round-tripped `output.inputs` is missing) and `t2i_privateGallery.add`
  (strip `undefined` values so the gallery never stores literal
  `"undefined"` strings). All deferred-install like the fly-to-gallery
  override.
- `src/lib/modals/modal.js` — generic shell both modals share (`createModalShell`,
  `closeModalShell`, `disposeEmbeds`, `makeModalButton`,
  `collectFinishedImages`, `restoreFinishedImages`, `makeReopenButton`,
  `addModalDismiss` (Esc + backdrop close), `makeBatchStash`,
  `resetProModal` (shared vary/style-compare destroy path). Closing a
  modal HIDES it (`display:none`) instead of destroying it, so reopening
  the same batch unhides the live iframes with their full in-frame UI
  (info/reload/gallery buttons) intact — no regeneration. A different batch
  destroys the old modal and builds fresh; `matches(data, hasLive)` covers
  both cases. Reset (`__proResetVary`/`__proResetStyleCompare`) still fully
  destroys.
- `src/lib/modals/vary-modal.js` — `openVaryModal`, `showReopenButton` (last-batch
  stash is file-scoped, not on `window`).
- `src/lib/modals/style-compare.js` — `getStyleTemplates`, `evalStyleStyles`,
  `openStyleCompareModal`, `showStyleCompareReopenButton` (stash also
  file-scoped).
- `src/lib/inspector/passes.js` — AI image inspector ("Retries" dropdown,
  `userInputs.passes`, 1-10, default 1 = off, frames untouched). On a frame's
  `finished` message it captures the seed, scores the image with
  `root.aiTextPlugin` (imported in `model.txt`; negative prompt = checklist,
  anatomy rubric always on) and, while the score is under 8, regenerates with
  the SAME seed in a hidden embed iframe, up to N tries. Best try stays on
  screen (a retry winner replaces the framework iframe with an `<img>` + save
  button; the iframe stays in the DOM, hidden, because the other buttons read
  it). Worse tries keep only a 320px thumbnail on `ctn.__inspRun`. Progress
  strip + chip on the frame. Inspector failure stops retrying (no blind spend).
- `src/lib/inspector/attempts-modal.js` — `openInspectorAttempts(ctn)`: per-try
  thumbnail, ACCEPTED/REJECTED/FAILED/UNJUDGED, score, defects, seed, time, and
  which try was kept. Opened by the 🔍 button / chip; live-updates during a run.
- `src/lib/gallery/dock.js` — bottom-center dock (`window.__refreshBottomDock`). Hides
  the docked gallery button while `#localMediaGallery_root` is open (it has
  its own close button) and adds 24px bottom padding to the gallery grid.
- `src/lib/prompt/migrate-steps.js` — one-time stale `(steps:::N)` cleanup.
- `src/lib/ui/open-links.js` — open links in a new tab (delegated).
- `src/lib/prompt/prompt-io.js` — export/import block (`#promptIoBar`, a small bordered
  block inline next to the "share these settings" button, styled to match
  it). Exports all 14 form fields (scratchpad, pre/post, description,
  negative, qualityBoost, numImages, artStyle, shape, Gscale, steps, seed,
  imagename, colorScheme) as JSON (`{app, format:1, exportedAt, values}`),
  gzip-compressed to `.json.gz` via native CompressionStream (plain `.json`
  fallback). "Export to text" downloads the four text fields (pre-prompt,
  prompt, post-prompt, negative — raw text only, no labels, blank-line
  separated) as `.txt`. Import accepts `.json` or `.json.gz` (magic-byte
  sniffed, DecompressionStream), restores via real `input`/`change` events so
  `window.input`, `remember` localStorage, and modifier dropdowns all update;
  unknown/removed select options are skipped with a count. No tar: single
  JSON is ~0.5KB and gzip already shrinks it ~30%.
- `src/lib/prompt/reset-defaults.js` + `src/defaults.json` — header "Reset" button.
  `defaults.json` maps each dropdown (qualityBoost, numImages, artStyle,
  shape, Gscale, steps, colorScheme) to its default option text — edit the
  JSON to change defaults, no code changes needed. Resets the 7 dropdowns
  plus the 4 prompt text fields (pre-prompt, prompt, post-prompt, negative —
  cleared to empty, preset chips/badges cleared too) and destroys the
  generated-images block plus any open Variations / Style Compare modals,
  their stashes and green/purple reopen buttons, back to fresh. Seed, title
  and notepad are not listed, so untouched. Choice persists via `remember`
  storage.
- `src/lib/ui/version-footer.js` — footer version badge: reads `src/VERSION.json`; clicking it opens `src/CHANGELOG.md` in a modal.
- `src/lib/ui/top-button.js` — `topBtn` scroll visibility + `topFunction()`.
- `src/lib/ui/bootstrap-enhance.js` — dark mode + Bootstrap class enhancement.
- `src/lib/ui/social-visibility.js` — hides the framework's comments/gallery
  containers while empty (they fill only after "show comments & gallery");
  re-shows on content via the central dispatcher.
- `src/lib/gallery/gallery-info.js` — private-gallery info-modal paint + close-btn fix.
- `src/lib/gallery/gallery-upscale.js` — injects a 🔍 button into each private-gallery
  photo bar (the plugin source is read-only, so injection via the central
  dispatcher). Loads the stored blob from the gallery's IndexedDB store
  (`localMediaGallery_.blobs`, DOM `<img>` fallback), converts to a data URL,
  shows the same bigger.pics confirmation as the main frames, then hands a
  complete `{dataUrl, inputs}` entry to the framework's upscale protocol
  (`window.t2i_pendingUpscales` + `window.t2i_showUpscaleLightbox`).
  The Okay handler opens the popup synchronously (popup-blocker safe); the
  framework-identical message listener is installed only if the framework
  hasn't installed its own yet. Also wraps `t2i_privateGallery.add`/`show`:
  after any external add (e.g. an upscale save) while the gallery is open,
  the view is rebuilt in place — debounced, preserving scroll position and
  sort order — so the new image appears without closing/reopening.
- `src/lib/gallery/gallery-more-menu.js` — retired (empty stub, no longer
  loaded). The `⋯` overflow-menu experiment was removed: on narrow frames the
  extra button wrapped into a second row. Replaced by `gallery-seed-bar.js`.
- `src/lib/gallery/gallery-seed-bar.js` — slim top bar injected into each
  private-gallery frame (mirrors the plugin's bottom bar, pinned to the top
  of the image; same hover-fade on desktop, always visible on touch, and it
  respects the gallery's hide-buttons toggle). Holds one button showing the
  image's seed (`📋 69683`); clicking copies it via `copyTextToClipboard`
  with a clipboard-API fallback and toasts the result. Missing/`-1` seeds
  render as `📋 no seed` with an explanatory tooltip.

## Steps (`(steps:::N)`)

`settings.userInputs.steps` is a dropdown: `20 (default)` first (marked
`meta:selected = true`), then `Off` (empty value), 1-30 plus 32/35/40/45/50 —
with plain `20` also in the list (duplicates are fine).

The token is appended **at generation time**, in `settings.imageOptions.prompt`
(`main.pjs`) — exactly how the Quality-boost `promptSuffix` is applied, and how
the style modifiers work. Nothing is written into the prompt textarea, so the
user's prompt box stays clean; the `(steps:::N)` tag only shows up in the prompt
that was actually used, i.e. in the generated image's info/"copy prompt" modal
(and in the vary/style-compare iframes, which inherit `prompt` from the image's
hash data).

IMPORTANT — what `(steps:::N)` does and doesn't do:

- It is **not** a real option of the image API. `text-to-image-plugin` only
  hoists a fixed whitelist of `(key:::value)` tokens out of the prompt
  (`seed|size|style|resolution|width|height|guidanceScale|saveTitle|saveDescription`
  — see the regex in `imports/text-to-image-plugin/main.pjs`), and the embed at
  `image-generation.perchance.org` POSTs only
  `{prompt, negativePrompt, seed, resolution, guidanceScale, referenceImage}`
  (`joinQueue` in the embed's source). There is no `steps` field and no
  `steps` token in either place.
- So `(steps:::N)` is passed through to the image model as **literal prompt
  text**. It's a label/annotation, not a control knob — it does not actually
  change the number of denoising steps. (Quality boost is different: its suffix
  is real descriptive text that the model reads.)
- It is kept because it is visible in each generated image's prompt info, which
  is what was requested. `Off` (empty value) means no tag is appended.

Notes for future work:

- The tag is appended after the art style's prompt and the quality-boost suffix.
- If a real steps control is ever wanted, it needs server support (the API has
  no such parameter today) — don't try to fake it with prompt text.
- Same seed + same prompt currently does **not** reproduce the same image
  (verified: 3 identical requests with the same seed returned 3 different
  images), so don't rely on seed reproducibility for A/B testing.
- Dropdown defaults are "(default)"-suffixed first options carrying
  `meta:selected = true`: qualityBoost → `Off (default)`, numImages →
  `3 (default) = 3`, artStyle → `No style (default)` (first in source —
  the framework ignores `meta:position = 0` because it truthiness-checks,
  so first position is done by source order), shape →
  `Square (768x768px) (default)`, Gscale → `12 (default) = 12`, steps →
  `20 (default) = 20`, colorScheme → Dark first. The plain value also stays
  in each list (e.g. plain `3` between 2 and 4) — duplicates are fine.
  The `default(X) = Y` pattern is NOT parsed by this framework version —
  it renders literally — so don't use it. Empty values use `Off = {|}`
  (steps, qualityBoost), which evaluates to `""`.
- `numImages`/`Gscale`/`steps` option lists are explicit (curated values,
  not ranges): the framework iterates option children, so a `{1-30}`
  shorthand would be a single option, not 30. Keep them literal.
